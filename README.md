[![Crates.io](https://img.shields.io/crates/v/daox.svg)](https://crates.io/crates/daox)

**Daox** is a cutting-edge engine that reads your databases and automatically generates the exact Rust code needed to communicate with them, safely and blazing fast.

This repository is the central workspace containing everything related to Daox (its core source code, tests, and documentation).

## 🏗️ Workspace structure

For advanced users and contributors, here is how the Daox ecosystem is organized as a Cargo workspace:

```text
daox-workspace/
├── docker-compose.yml      # Automated Database Deployment (PostgreSQL, MySQL)
├── init_*.sql              # Database schemas loaded automatically upon Docker start
├── daox/                   # The core framework (this is what gets published to crates.io)
│   ├── src/                # Dialect builders, AOP parsers, macro logic
│   └── assets/             # Explanatory SVG architecture diagrams
│
└── daox-test/              # Comprehensive Integration Test Suite
    ├── src/models/         # Code fully auto-generated by Daox (via build.rs)
    └── src/main.rs         # The testing workflows (Streams, Pagination, Upserts, etc.)
```

## 🧪 How to run the Integration Tests locally (Pedagogical Guide)

If you cloned this repository and want to verify that Daox works, or if you wish to contribute to the code, follow these exact unambiguous steps:

### Prerequisites

You strictly need:

1. **Rust** installed on your computer.
2. **Docker** and **Docker Compose** installed (to launch our test databases safely without polluting your machine).

### Step 1: Launch the test databases

Daox requires living databases to test its core logic. We provide a pre-configured `docker-compose.yml` file. Open your terminal at the root of `daox-workspace` and run:

```bash
docker compose up -d
```

_What happens?_ Docker will download and silently run a PostgreSQL database (on port 5433) and a MySQL/MariaDB database (on port 3307). We use specific ports to guarantee they will never conflict with your existing local projects.

### Step 2: Run the test suite

Navigate into the test directory.
Here, the `build.rs` script will connect to the databases you just launched, automatically generate the Rust files, and then the test runner (`main.rs`) will validate every feature (Upserts, Patching, Streaming, etc.).

```bash
# 1. Enter the test directory
cd daox-test

# 2. Test the SQLite engine (Runs completely isolated locally, no Docker needed)
DAOX_TEST_SQLITE=1 cargo run

# 3. Test the MySQL / MariaDB engine (Connecting to the Docker container)
cargo run

# 4. Test the PostgreSQL engine (Connecting to the Docker container)
DAOX_TEST_PG=1 cargo run
```

If the terminal output shows tests executing without crashing, the entire framework is mathematically proved to be functioning perfectly on your machine!
